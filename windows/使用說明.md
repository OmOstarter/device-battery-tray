# 裝置電量系統匣小工具

雙擊 `DeviceBatteryTray.exe` 即可啟動，不需要系統管理員權限。原有三款型號各自使用獨立系統匣圖示：LOFREE 小順青春版(100鍵)、HECATE G3M PRO、HECATE G3M PRO 升級版。

- 鍵盤使用鍵盤圖示，兩支滑鼠各自使用滑鼠圖示。
- 超過 70%：綠色。30% 至 70%（包含端點）：橘色。低於 30%：紅色。
- 游標懸浮可查看裝置名稱與百分比。
- 裝置或接收器拔除後，系統匣圖示與卡片於下次刷新隱藏；仍插著但讀取失敗時顯示灰色，不保留過期百分比。
- 每 30 秒重新偵測與刷新；右鍵可以立即刷新、查看全部電量、設定登入 Windows 時啟動、結束全部圖示。
- 同一時間只會執行一份程式。

若圖示在右下角的「^」隱藏圖示區，可將三個圖示分別拖至工作列的系統匣可見區。Windows 控制這項顯示位置設定。

## 相依與實測範圍

原有讀取流程可使用本機已安裝的原廠 DLL；若使用此流程請保留 `C:\Program Files\HECATE` 與 `C:\Program Files\Lofree Key Mapper\Sys64`。原廠驅動視窗不需要開啟。v0.1.1 在缺少 DLL 時會改用 Windows 內建 HID 後端；新增協定項目也使用內建 HID，不需額外安裝原廠 DLL，但仍須正確相容的設備協定。程式不包含或散布原廠 DLL，不依賴 Python。

已在此電腦實際讀取三個裝置，鍵盤先讀到 95%，後續讀到 100%，兩支滑鼠均為 100%。後續已實測兩支滑鼠的 2.4 GHz 接收器：原版 98%、升級版 100%。藍牙與同型號多台裝置尚未驗證。

目前辨識：鍵盤 `05AC:024F`、原版滑鼠 `320F:706B / 706E`、升級版 `35BB:D3FC / D3FB`。每個型號各一個圖示，僅在裝置或接收器插入時顯示；重新接回時自動偵測，最多等待 30 秒。當全部圖示隱藏時，再次執行程式即可開啟現有總覽。

## 原始碼與診斷

`DeviceBatteryTray.cs`、`DeviceProfiles.cs` 和 `ProfileTests.cs` 為 C# 原始碼與測試；執行 `build.ps1` 可使用 Windows 內建 .NET Framework 編譯器重新建置 64 位元版本。

程式會在同目錄更新 `status.json`，包含讀取時間、百分比及原始回應；不連線上傳資料。

命令列診斷：`DeviceBatteryTray.exe --diagnose status.json`。顏色邊界與圖示建立檢查：`DeviceBatteryTray.exe --self-test`。

## 通訊逆向筆記

分析來源為此電腦安裝的 `HIDUsb.dll` 匯出函式及反組譯，以及 LOFREE 安裝目錄附帶的 COFF 編譯檔。未修改原廠安裝檔、韌體、按鍵設定或 DPI。

1. LOFREE：`functionset.obj` 的 `FunctionSet::Get_KB_Battery` 與 `USB_Load_Data` 顯示電量命令為 17 bytes，前兩 bytes 為 `08 04`，第 5 個零起算欄位必須為 `80`（讀取旗標）。最後一 byte 是 `55 - sum(前16bytes)`，以 8 位元截斷。透過 `UsbFinderC_OpenDevice`、`UsbFinderC_ReadWriteDeviceData(request, response, 17)`、`UsbFinderC_CloseDevice` 查詢；回應零起算 byte 6 為電量。直接使用舊版同步 `UsbFinderC_GetBatteryLevel` 會缺少讀取旗標，在此鍵盤回傳全零，因此未採用。
2. 原版 G3M PRO：舊版 HECATE Connect 執行檔內 `0x47FCA0` 建立電量查詢，`0x47C9F0` 執行寫入／讀取。控制集合為 usage page `FF1C`，64 bytes 請求開頭 `04 20 00 1A 06 00 00 00`，其餘為零；回應 byte 8 為百分比。程式檢查長度、報告 ID、命令及錯誤狀態，且限制讀取等待時間。
3. 升級版 G3M PRO：原廠 `data\devices\002_g3mpro_upgrades.json` 提供 VID/PID；控制集合為 `FF02`。呼叫 `UsbMouseC_GetBatteryLevel`，回應結構第一 byte 為百分比。

僅對已辨識的廠商控制集合發出上述電量查詢，不讀取鍵盤按鍵或滑鼠操作內容。


## 接收器修正（2026-11-08）

補上原版 G3M PRO 接收器 PID 706E；有線 PID 706B 仍保留。升級版接收器 PID D3FB 已實測讀值，並加入失敗重試。懸浮提示與全部電量視窗會標明 USB 或 2.4 GHz 接收器。更新時請先從任一圖示右鍵選擇「結束全部圖示」，再重新啟動程式。


## 新版介面與自訂名稱

啟動時顯示卡片式裝置總覽，預設深色模式；右上角可切換深色／淺色模式。關閉視窗後三個系統匣圖示仍持續執行，雙擊任一圖示可重新開啟總覽。

每張裝置卡片都有「重新命名」，名稱最多 32 個字元且不可空白；儲存後同步至卡片、懸浮提示與右鍵選單。名稱及顯示模式儲存於程式旁的 preferences.json，重新啟動後保留。若要分享原始碼到 GitHub，請勿附上自己的 preferences.json 或 status.json。

鍵盤的有線與 2.4 GHz 模式同為 05AC:024F；以 HID 產品描述 Air100@Lofree / 2.4G Wireless Receiver 區分。接收器電量已實測 100%。


## v0.1.1 新增／編輯／刪除裝置

- 按「新增裝置／USB 拔插」：列出目前 USB 實體設備，每秒在背景檢查拔插，並保留最近 200 筆紀錄。拔掉目標鍵盤、滑鼠或 2.4 GHz 接收器，再插回，就能辨認名稱及 VID／PID。複合 USB 介面會合併；可複製設備資料，或把仍連接的設備加入監測。
- 新增 USB 項目先顯示連接狀態；如要讀取電量，按卡片的「編輯協定代碼」。自訂項目可重新命名、刪除，並有獨立系統匣圖示。刪除只移除監測設定，不會移除驅動或解除配對。
- 「輸入協定代碼」有簡易填寫、協定代碼、本地 agent 提示詞三頁。填設備名稱、VID／PID（十六進位字串）、連線方式、原廠軟體／DLL 路徑及鍵數等資訊，會自動產生可複製的提示詞；程式不會自行啟動 agent 或反編譯驅動。
- 確認相容時可選 `lofree`、`hecate-original`、`hecate-upgraded` 產生代碼，也可貼上 JSON 或 `DBT1:` 代碼。儲存後保留設定並重新讀取；編輯會替換原項目。原廠路徑及說明會保存，以便再次編輯。
- 未知協定不能任意套用現有名稱。提示詞要求 agent 提供分析證據，必要時先實作後端，再產出可匯入代碼。程式只對指定 VID／PID 的廠商控制介面發送已有的電量查詢；逾時會顯示狀態，不保留舊電量。

JSON 範例：`{"version":1,"name":"LOFREE 小順青春版","vid":"05AC","pid":"024F","protocol":"lofree"}`。原有型號本來會自動偵測，這個例子只說明格式。只有已確認使用相同協定的其他型號才適用。

Windows 新增設備功能使用系統 WMI／SetupAPI／HID；本版未加入通用藍牙電量來源。同 VID／PID 的多台設備可用 USB 設備識別路徑分辨拔插，但協定代碼仍以 VID／PID 選設備，尚不支援為同型號多台分別綁定查詢。

驗證：`DeviceBatteryTray.exe --test-profiles` 檢查代碼解析、封包、設定往返、USB 變動及編輯介面；`--self-test` 檢查既有型號、顏色及圖示；`--preview-ui <PNG路徑>` 產生總覽預覽。GitHub Actions 在 Windows 執行這些檢查；新功能仍需要使用者在實際鍵鼠上確認讀值。
